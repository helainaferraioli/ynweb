Section A · Filing System

Where everything lives

As of this cleanup (Sept 13, 2026), there are exactly two places to look. If it's not one of these two, it isn't part of the site.

1. The project itself — everything currently live or about to be

Desktop › YN Site is the actual project: a Git repository that Vercel builds and publishes as yesterdaysnewsbk.com. Nothing outside this folder affects the live site.

  • public/ — every photo, video, and icon the site can show, exactly as filed. If it's in here, it's live or about to be.
    • images/about/, images/we buy/, images/ephemera/ — photos grouped by the page that uses them
  • src/app/ — one folder per page
    • page.tsx — Home
    • about/, shop/, contact/, we-buy/, faq/, policies/
    • api/ — the plumbing: email, payments, photo uploads
    • studio/ — hosts the Sanity product database at /studio
  • src/components/ — reusable pieces pages are built from (Navbar, Footer, AboutSlideshow, WeBuyQualify, …)
  • sanity/schemas/ — product.ts and order.ts, the shop's data model
  • docs/ — two living planning documents, plus this manual
    • yn-site-edits.md — the running punch-list of copy/photo changes
    • yn-site-pickup-shop-spec.md — how the pickup-only shop is meant to work

2. The archive — everything else, organized

Desktop › Yesterday's News Archive is new: a single home for every loose photo, old draft, and export that was scattered across the Desktop and Downloads. Nothing was deleted — items were moved and sorted, so near-duplicate folders (like the two "YN Website Assets" folders) sit side by side rather than being merged.

Safe to Delete

An empty file, an old build folder, one exact-duplicate photo. Nothing here is used anywhere — empty this whenever you like.

B
Section B · Copy & Photos

Making a change

This site is hand-built, not a drag-and-drop page builder — with one exception (the shop's products, see Section C). That means the wording you see on the page is typed directly into a file, and changing it means editing that file and republishing. It's quick, but it does need to go through code.

The easiest way to do this: describe the change to Claude Code in plain language ("change the opening line on the About page to...") and let it find the right file, make the edit, and check it before it goes live.

The routine

  1. Say what you want changed, and where. Either ask directly, or add it to the running list at docs/yn-site-edits.md — that file already exists for exactly this, tagged by page and type (Copy, Sizing, Graphic/Photo, Bug).
  2. The file gets edited. Wording lives in the page file (src/app/about/page.tsx, for example) or a shared component (src/components/). Swapping a photo means dropping the new file into the matching public/images/… folder and pointing the page at its filename.
  3. Preview it. Running npm run dev opens a local copy at localhost:3000 that reflects the change instantly, before anyone else sees it.
  4. Publish it. Once it looks right, the change is committed and pushed to main — see Section E, Publishing Day. That's the only step that makes it visible to customers.
Good to know Prices, hours, and copy that mention "25 years" or specific ages are typed as plain text, not calculated automatically — they'll need a manual touch-up each year rather than updating themselves.
C
Section C · Inventory

Running the shop

Products are the one part of the site that doesn't require touching code. They live in Sanity, a small database with its own editing screen built right into the site.

Open yesterdaysnewsbk.com/studio (or localhost:3000/studio while testing locally) and sign in with the studio username and password — see Section F, The Vault, for where those are kept.

Adding a piece

Inside Studio, choose Product › Create new and fill in:

FieldWhat it's for
Title, DescriptionWhat shows on the product page.
PriceIn dollars — this is what Stripe charges at checkout.
PhotosAt least one required; the first is used as the cover image.
Dimensions, Materials, ConditionShown in the item's details table (e.g. "Excellent" / "Good" / "Fair").
Quantity Total / AvailableAvailable drives the "Last one" and "Sold out" badges automatically.
StatusDraft → Scheduled → Live → Sold Out → Archived. Set to Live when it's ready to sell.
Posted AtDrives the "New" badge for the first ~7 days.
Current limitation The public Shop page (/shop) still shows a "New items dropping soon" placeholder — it isn't wired up yet to display a browsable grid of live products. A product's own page (/shop/<product-id>) already works completely — photos, price, checkout, and pickup scheduling all function — it just isn't linked from anywhere public yet, so today it can only be shared as a direct link. Building that grid is the next piece of shop work.

The intended shop rules — pickup only, no shipping, pickup hours, and the no-show/forfeiture policy — are written out in full in docs/yn-site-pickup-shop-spec.md.

D
Section D · What Happens Behind the Counter

Mail & messages

  • Contact form

    Submissions on the Contact page are sent by Resend straight to the shop's inbox.

  • We Buy lead form

    Captures sell-your-stuff inquiries; a photo-upload field (powered by Uploadthing) lets sellers attach pictures of what they're offering.

  • Instagram feed

    The homepage feed pulls recent posts from @yesterdaysnewsbk using an access token that periodically expires and needs refreshing — a maintenance task, not a one-time setup.

  • Map

    The embed on the Contact page runs on a Google Maps key — no action needed unless it stops rendering.

E
Section E · Going to Press

Publishing day

There's no separate "publish" button to remember — the site deploys itself the moment code changes reach the right place.

To…Do this
Preview a change privatelynpm run dev, then open localhost:3000
Check it compiles cleanlynpm run build — worth running before a bigger change
Make it live for customersPush the change to main — Vercel (project ynweb) builds and deploys automatically, usually within a couple of minutes
Safety net If a pushed change fails to build, Vercel keeps the last working version live rather than replacing it with a broken one — the site won't go down from a bad push.
F
Section F · Keys & Combinations

The vault

The site talks to several outside services (payments, email, uploads), and each one hands it a private key to prove who's asking. Locally those keys sit in .env.local — a file that is deliberately never saved to Git, so it never leaves your computer by accident. In production, the same keys are set separately inside the Vercel dashboard for the ynweb project (Settings › Environment Variables).

  • RESEND_API_KEY

    Sends contact-form emails.

  • UPLOADTHING_SECRET / UPLOADTHING_APP_ID

    Runs the We Buy photo upload.

  • NEXT_PUBLIC_GOOGLE_MAPS_API_KEY

    Draws the map on the Contact page.

  • NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY / STRIPE_SECRET_KEY / STRIPE_WEBHOOK_SECRET

    Runs shop checkout and confirms payment.

  • SANITY_API_TOKEN

    Lets the site read and write product & order data.

  • STUDIO_USERNAME / STUDIO_PASSWORD

    The password gate on /studio.

  • INSTAGRAM_ACCESS_TOKEN

    Powers the homepage Instagram feed.

House rule Never paste a key into an email, text, or chat, and never commit .env.local. Ask before regenerating any key — rotating one breaks whatever uses the old value until it's updated in both places, locally and in Vercel.

H
Section H · For the Uninitiated

Plain-English glossary

Repo
The project folder itself — tracked by Git, so every change has a history.
Commit / push
Saving a change (commit), then sending it to GitHub (push) — the trigger that starts a deploy.
Deploy
Publishing the current code so it's what visitors actually see.
Vercel
The hosting service that builds the site and serves it at yesterdaysnewsbk.com.
Sanity / Studio
The shop's product database, and its editing screen at /studio.
Stripe
Processes the actual card payment at checkout.
Resend
Delivers the contact form's emails.
Uploadthing
Handles photo uploads from the We Buy form.
API key
A private password that lets the site talk to an outside service without that secret appearing in the code.
.env.local
The file holding those keys on your computer — never shared, never committed.

Section I · Corrections

If something breaks

Quick checks

  • Site looks wrong after a push — check the deployment log for the ynweb project in the Vercel dashboard; a failed build leaves the previous working version live.
  • Can't log into /studio — confirm STUDIO_USERNAME/STUDIO_PASSWORD match what's set in Vercel, not just .env.local.
  • A form isn't arriving — check the Resend or Uploadthing dashboard for a failed send before assuming the form itself is broken.
